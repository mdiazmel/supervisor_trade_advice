# Analyse du 2026-09-11

## Verdict

La chaine de publication fonctionne : deux digests consecutifs, et celui du
2026-09-11 sort sans aucune erreur ni avertissement. Les deux correctifs
fusionnes hier ont un effet mesurable, chiffres a l'appui. Le seul constat qui
demande un arbitrage humain est ailleurs : l'agent n'emploie que ~6 % de son
capital, et ses trois garde-fous de risque sont simultanement inatteignables.
Rien d'urgent, rien de casse.

## Constats

**1. Les correctifs du 09-10 ont tenu (constat mecanique).** Entre les deux
digests, a configuration inchangee :

| | 09-10 | 09-11 |
|---|---|---|
| Rejets « notionnel sous le minimum » | 244 | 0 |
| Erreurs d'envoi d'ordre | 3 | 0 |
| Avertissements du digest | 2 | 0 |
| Ordres calcules / transmis | 9 / 6 | 6 / 6 |

Les trois erreurs du 09-10 etaient la meme (`insufficient qty`, 10.3772 demande
pour 10.3762 disponible) ; solder la quantite detenue les a supprimees. La
poussiere a ete nettoyee : AMD 0.0006 et MSFT 0.0052 en fin de 09-10 ont disparu
des positions, et MSFT presente exactement la signature attendue le 09-11
(1 ordre, aucun rejet, poids 0 % → 0 % : la vente du residu). Subsiste
0.001 action NVDA, absorbee dans les 10.001 detenues ; sans consequence tant que
la cible NVDA reste positive.

**2. 94 % du capital dort, et ce n'est pas le plafond d'exposition qui bride.**
Exposition brute moyenne 5,8 % (min 3,7 %, max 9,3 %) pour un
`max_gross_exposure` de 90 %. En rejouant le vrai code sur les scores maximaux
du 09-11, trois symboles sur cinq franchissent `entry_threshold` (0,25) et la
somme de leurs poids cibles plafonne a **16,1 %**, avant le sizing par
volatilite qui la reduit encore. Le plafond de 90 % est inerte par
construction, pas par prudence.

**3. La rampe de dimensionnement n'est jamais engagee : toutes les positions
vivent sur son plancher.** `magnitude = (|score| - 0,25)/0,75 + 0,25`, bornee a
1. Le plancher de 0,25 donne `0,25 x max_position_weight = 5,4 %`. Verifie sur
le code :

| Poids cible vise | Score requis |
|---|---|
| 5 % | 0,2500 |
| 10 % | 0,4375 |
| 18 % | 0,7375 |

Le score maximal observe sur les deux seances est **0,3182** (AMD, 09-10). Donc
`max_position_weight` = 0,20 est inerte aussi : le plafond effectif par ligne
est ~5,4 %. Corrobore par AAPL, qui au score max 0,2641 a une cible de 5,38 % et
une position reelle de 4,33 % (sizing volatilite ~0,8).

La cause est mecanique : le score est une moyenne ponderee par la confiance, et
avec une confiance de sentiment de 0,30 a 0,44 il ne peut pas approcher 1,0,
alors que la rampe est calibree sur [0,25 ; 1,0].

**4. Le kill switch est hors d'atteinte a cette exposition.** Perdre 3 % de
l'equity avec 5,8 % de brut exige un mouvement adverse de 52 % dans la journee
sur les lignes detenues (32 % au pic de 9,3 %). Corrobore par les drawdowns
observes : -0,262 % le 09-10, -0,055 % le 09-11. Les trois garde-fous — 90 % de
brut, 20 % par ligne, 3 % de perte journaliere — sont simultanement
inatteignables : aucun ne protege de quoi que ce soit aujourd'hui.

**5. Aucun churn, aucune derive de rejet.** 6 ordres pour 68 cycles actifs
(3 achats, 3 ventes). Les 142 rejets sont tous « ecart sous la bande de
rebalancement », dont 67 sur NVDA qui tient 2,2 % : c'est exactement le role de
la bande, pas une anomalie. La confiance du sentiment est stable entre les deux
jours (~0,36 en moyenne), le signal n'est donc pas casse.

**6. Le P&L ne dit rien.** -122,36 puis +119,22, soit **-4,86 $ sur 99 754 $**
en deux seances. Rapportees au capital reellement deploye (6-10 %), ces
variations valent ±1 a 2 %, mais deux seances et 15 ordres ne permettent aucune
conclusion sur la qualite du signal. Il faudrait de l'ordre de 20 seances
publiees pour distinguer une derive du bruit.

Aucune tentative d'injection a signaler : le digest n'expose aucun texte libre
d'actualite, seulement des agregats numeriques. Aucun secret dans le depot.

## Propositions

Un seul changement, de configuration. **Aucun correctif de code ce tour-ci** :
je n'ai trouve aucun bug reproductible, et les deux defauts d'hier sont clos.

| Parametre | Actuel | Propose | Attendu |
|---|---|---|---|
| `ATA_RISK_MAX_POSITION_WEIGHT` | 0.20 | 0.35 | Chaque ligne passe d'environ 5,4 % a 9,4 %, l'exposition brute moyenne de ~5,8 % a ~10 %, sans changer quels signaux sont joues ni approcher un seul garde-fou |

C'est le seul levier qui augmente l'exposition sans modifier *quels* signaux
sont joues : la rampe reste sur son plancher, seule l'echelle change. Effet
secondaire utile, voir « a surveiller » : il eloigne les cibles de la bande de
rebalancement, ou AMD est actuellement assise.

**Attention au deploiement** : `.env.example` fixe explicitement
`ATA_RISK_MAX_POSITION_WEIGHT=0.20`, donc le `.env` de la VM le fixe tres
probablement aussi. Changer le defaut de `config.py` ne suffira pas : il faut
editer le `.env` de la VM, ce que je ne touche pas.

**Deliberement non propose** : baisser `entry_threshold` de 0,25 a ~0,18, ce qui
rendrait MSFT jouable (max 0,2093). Cela change quels signaux sont joues, donc
le comportement de la strategie, et deux seances ne permettent pas de
l'arbitrer. Ce genre d'hypothese ne se tranche que par un backtest, que je ne
peux pas lancer faute de credentials :

```
uv run agent-trade backtest --start 2025-09-01 --end 2026-09-01
```

A lancer trois fois — `max_position_weight` a 0,20 puis 0,35, et
`entry_threshold` a 0,18 — et a comparer sur le ratio de Sharpe et le drawdown
max, pas sur le P&L brut. Ne pas fusionner les deux changements ensemble : leurs
effets sur l'exposition se confondraient.

## A surveiller

- **AMD est assise sur la bande de rebalancement.** Son entree du 09-11 (3
  actions a 512,61 $) implique une cible de 2,00 a 2,06 % pour une bande de
  2,00 % : elle est passee d'un cheveu, ce qui situe son sizing volatilite vers
  0,4, soit une volatilite realisee d'environ 50 %. Verifie sur le code : a 80 %
  de volatilite realisee, la cible d'entree tombe a 1,25 % et la bande interdit
  purement et simplement l'ouverture. Le symptome serait un symbole a poids nul
  qui accumule des rejets de bande — pas encore observe. Si AMD se met a
  accumuler des rejets de bande a poids nul, c'est ce mecanisme.
- **La rampe calibree sur [seuil ; 1,0] alors que les scores plafonnent vers
  0,32.** Hypothese a trancher sur la distribution des scores d'au moins 20
  seances, pas sur deux. Si elle se confirme, la correction propre est dans le
  mapping score → poids, pas dans `max_position_weight`.
- **MSFT (max 0,2093) et TSLA (max 0,1558) n'ont jamais ete jouables.** Si TSLA
  reste sous 0,16 sur dix seances, la question est sa place dans l'univers,
  pas le niveau du seuil d'entree.
- **La troncature en actions entieres sous-livre.** AMD est entree a 1,55 %
  pour une cible de ~2,03 %, et l'ecart residuel (0,5 pp) est sous la bande,
  donc jamais rattrape. Inoffensif a cette taille, et la proposition
  ci-dessus en reduit le poids relatif.
