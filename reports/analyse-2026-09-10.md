# Analyse du 2026-09-10

## Verdict

L'agent n'a publie aucun digest : le depot de digests ne contient que son
`README.md` depuis sa creation le 2026-09-07 a 22h51. Aucune conclusion sur la
strategie n'est possible — zero observation. En revanche la chaine de
publication est cassee de facon mecanique, et la cause principale survit aux
deux correctifs pousses aujourd'hui : le garde-fou « digest inchange » de
`push-digest.sh` aurait bloque la publication tous les soirs, pas seulement la
premiere. Une branche le corrige.

## Constats

**1. Deux fenetres de publication manquees, zero digest.** Le timer
`agent-trade-digest.timer` tourne `Mon..Fri 21:30`. Le depot a ete cree le
lundi 2026-09-07 a 22h51, donc apres la fenetre de lundi ; les fenetres du
mardi 09-08 et du mercredi 09-09 sont passees sans rien produire. Celle de ce
jour n'a pas encore eu lieu (il est 18h49). Constat mecanique, pas une
hypothese : `git log` du depot de digests ne contient qu'un commit,
`7b1e6b4 first commit`, avec le seul `README.md`.

**2. Une premiere cause est documentee dans le code, et deja corrigee — mais
trop tard pour ces deux jours.** Le commentaire de `push-digest.sh`
(lignes 25-29) decrit un `.env` source comme un script shell, qui mourait en
127 sur `ATA_..._CRON=30 22 * * 1-5` avant toute publication. Les correctifs
sont d'aujourd'hui : `2c391e5` a 18h19 et `58b3a76` a 18h27, soit apres les
deux fenetres. La chronologie est coherente, mais ce n'etait pas le seul
obstacle (constat 3) : les deux defauts coexistaient, et je ne peux pas
attribuer les deux journees blanches a l'un plutot qu'a l'autre sans les
journaux de la VM (`journalctl -u agent-trade-digest`).

**3. Aucun digest quotidien n'aurait jamais ete publie, meme apres ces
correctifs.** C'est le constat le plus important, et il est mecanique. Le
garde-fou « digest inchange » utilise :

```bash
if git -C "$CLONE_DIR" diff --quiet -- reports; then
```

`git diff` ignore les fichiers non suivis. Et `write_digest` nomme ses fichiers
`digest-{period_end}.json` et `.md` (`supervisor/digest.py` ligne 351) : chaque
journee produit donc de **nouveaux** fichiers, untracked, invisibles pour
`git diff`. Le script affiche « Digest inchange, rien a pousser » et sort 0. Le
timer systemd enregistre un **succes**, et rien n'est publie — sans aucun signal
d'erreur nulle part.

Ce n'est donc pas un simple probleme d'amorcage. Reproduit sur des depots
temporaires :

| Situation | Ancienne logique |
|---|---|
| Premier digest, `reports/` jamais suivi (etat actuel du depot) | rien a pousser |
| Nouveau jour ajoute sur un depot deja peuple | rien a pousser |
| Regeneration du meme jour, contenu different | publication |

Le seul cas qui publiait est la regeneration d'un digest du **meme** jour avec
un contenu different, c'est-a-dire un fichier deja suivi. Corriger le `.env` et
l'uid du conteneur (constat 2) etait donc necessaire mais pas suffisant : ce
garde-fou aurait bloque la publication tous les soirs.

**4. Le deploiement doit etre rafraichi avant la fenetre de ce soir.** Les
correctifs 2-3 sont dans le depot, pas necessairement sur la VM. Le commit
`0b2c2dd` note lui-meme que les ressources sont figees au provisionnement.
Sans `git pull` sur `/opt/agent-trade-alpaca` (plus la fusion de la branche
proposee), la fenetre de 21h30 de ce soir sera la troisieme perdue.

**5. Secondaire : la suite de tests parait rouge alors que le code est vert.**
`.python-version` pinne `3.14` (3.14.0rc2), sur lequel pydantic ne peut pas
construire les modeles : `uv run pytest` echoue au collect
(`TypeError: _eval_type() got an unexpected keyword argument
'prefer_fwd_module'`). La CI ne teste que 3.12 et 3.13, mypy cible 3.12 : rien
ne couvrait 3.14. Sur 3.12 comme sur 3.13, `195 passed, 4 skipped`. Le code va
bien, c'est l'interpreteur pinne qui casse la commande de verification
recommandee par la procedure.

**Pas de fuite de secret.** `.env.example` ne contient que des cles vides ; les
seules chaines ressemblant a des credentials sont des fixtures de test
volontairement factices dans `tests/test_supervisor.py`. Aucune tentative
d'injection a signaler, faute de contenu de digest a analyser.

## Propositions

Aucun changement de parametre de strategie : avec zero digest, il n'y a rien
sur quoi fonder un reglage. Les deux propositions ci-dessous concernent la
chaine d'observabilite, sans laquelle aucune supervision n'est possible.

| Parametre | Actuel | Propose | Attendu |
|---|---|---|---|
| Garde-fou de publication, `deploy/push-digest.sh` | `git diff --quiet -- reports` | `git add -A reports` puis `git diff --cached --quiet -- reports` | Le digest du jour est reellement publie, alors que le garde-fou actuel le bloque chaque soir, sans reintroduire de commit vide quand le digest est inchange |
| `.python-version` | `3.14` | `3.13` | `uv run pytest` redevient executable sur l'interpreteur pinne, alignee sur la version la plus haute couverte par la CI |

## A surveiller

- **La strategie elle-meme est entierement non evaluee.** Equity, drawdown,
  exposition brute, motifs de rejet, confiance du sentiment, nombre d'ordres :
  aucune valeur disponible. Il faudra au minimum cinq seances publiees avant
  qu'une derive soit distinguable du bruit ; le premier digest ne permettra que
  de verifier que la chaine fonctionne et que les champs sont plausibles.
- **Un digest publie ne prouve pas que l'agent a trade.** Au premier digest,
  verifier separement que le runner a bien tourne les jours couverts : un
  digest vert sur une periode sans activite ressemble beaucoup a un digest vert
  sur une periode ou tout a ete rejete.
- **Echec silencieux du timer.** Le mode de defaillance rencontre ici — sortie
  0, succes systemd, rien de publie — n'est detectable qu'en regardant le
  depot. `check_digests_available` couvre le cas au provisionnement ; rien ne
  le couvre au quotidien. Si une deuxieme journee blanche survient apres la
  fusion, la piste a instruire en priorite est une alerte cote VM lorsque le
  dernier commit du depot de digests date de plus de 24 h ouvrees.
- Aucune hypothese ne demande de backtest a ce stade : sans digest, il n'y a
  aucune hypothese de strategie a trancher.
